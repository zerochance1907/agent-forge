# Cycle 2026-11-11 — Preflight

## The idea

**Preflight** — a deterministic *blast-radius classifier* for agent shell
commands. Given a proposed command, it assigns one of five risk tiers
(`SAFE / REVERSIBLE_LOCAL / DESTRUCTIVE_LOCAL / EXTERNAL / UNKNOWN`) from the
command structure, and for local-tier commands enriches the card with the
*live working-tree delta* (how many files the command touches, and how many of
those hold uncommitted work). It is the "informed half" of human-in-the-loop
approval: pause only for the commands that actually matter, and tell the human
exactly why. A standalone stdlib + `git` CLI — no model, no network, no GPU,
nothing vendored.

Why it was picked over the debate's other finalist (SignalLoss): Preflight's
core is a pure self-contained function, so three independent builders could
produce *comparable* artifacts in a few hours; SignalLoss's comparability hinged
on an upstream-install gamble (a Rust binary + a trained model on a no-GPU
Windows box). That bet paid off — see below.

## How well it worked

The spec did its job. All three builds are honest and genuinely functional.
Forgejury graded **3/3 PASS** (every spec-axis file/symbol/test check, every
`claims.json` claim matched a fresh run, and all 9 consensus fixtures agreed
3-0). I re-ran everything and confirmed it independently:

- **Tests:** exec-1 48 passed, exec-2 93 passed, exec-3 74 passed — all green.
- **Demo + gate semantics:** identical and correct across all three. Default
  `gate` pauses on everything (exit 10); `--auto-approve-safe` only ever
  auto-approves `SAFE`/`REVERSIBLE_LOCAL` and never `DESTRUCTIVE_LOCAL`,
  `EXTERNAL`, or `UNKNOWN`.
- **Tree enrichment:** I built scratch git repos (3 untracked files; and a mixed
  1-committed-plus-2-dirty case). All three correctly reported
  `files_affected=3` and `uncommitted_at_risk` of 3 and 2 respectively.
- **Edge-case tier battery (18 cases beyond the fixtures):** `find -delete`,
  `git checkout -- file`, `git reset HEAD` (no `--hard`), `echo >` vs `>>`,
  `docker build` vs `docker push`, `npm run` vs `npm install`, pipes, etc. —
  **all three agreed and were correct on every one.** The pinned precedence
  table produced three indistinguishable classifiers.

Because behavior converged completely, the builds separate only on code quality
and novelty of execution.

## The three builds

| Axis | exec-1 (minimalist) | exec-2 (production) | exec-3 (wild) |
|---|---|---|---|
| Meets acceptance criteria | 10 | 10 | 10 |
| Works when run | 10 | 10 | 10 |
| Code quality | 8 | **9** | 7 |
| Novelty of execution | 5 | 6 | **8** |
| Tests | 48 | **93** | 74 |
| LOC (preflight.py) | 325 | 303 | 437 |
| **Overall** | 8.0 | **8.9** | 8.2 |

- **exec-1 — minimalist.** 325 clean lines, string-input `classify_command`,
  correct, lean; `tier` avoids spawning `git`. The least differentiated card
  (plain key/value) and the fewest tests, but nothing wrong with it.
- **exec-2 — production. (winner)** Type-hinted, with the most robust engine:
  it tokenizes via `shlex.shlex(punctuation_chars=...)` so shell operators and
  `>` vs `>>` are *exact token matches* rather than regex heuristics on the raw
  string. Named sub-command sets, cleanest separation, accepts both a string
  and a token list, 93 tests, zero defects found. The strongest reference build.
- **exec-3 — wild.** The most novel demo: a human-readable "blast radius map"
  rendered from the *real* `files_affected`/`uncommitted_at_risk` numbers (more
  `✖` = visibly denser danger; `EXTERNAL` ripples out; `UNKNOWN` is fog),
  plus a genuine Windows UTF-8 console fix. But two dings: its
  `classify_command` takes a **token list only** — calling it with a command
  *string* (`classify_command("rm -rf build")`) iterates the string
  character-by-character and returns a wrong `UNKNOWN`, diverging from the
  spec's "core function" contract and from the other two builds. Its documented
  PreToolUse hook uses the CLI, so the wart is latent rather than a broken demo,
  but a library consumer would hit it. Also a small dead-code fragment in
  `_has_obfuscation`.

## Winner: exec-2

It is the build I would put in front of you as the reference implementation:
the most robust classifier, the most tests, a correct library API, and a clean
card — with no defects surfaced under independent testing. exec-3's map is the
better *demo* and worth borrowing, but its token-list-only core function is a
real divergence; exec-1 is clean but the least differentiated.

### How to run it

```
cd builds/2026-11-11/exec-2
python -m pytest -q                              # 93 passed
python preflight.py classify -- rm -rf build     # the blast-radius card
python preflight.py --auto-approve-safe gate -- ls -la   # AUTO-APPROVED SAFE, exit 0
python preflight.py --auto-approve-safe gate -- rm -rf . # PAUSE DESTRUCTIVE_LOCAL, exit 10
```

(`files_affected`/`uncommitted_at_risk` are non-zero when a real `build/` dir
with tracked/untracked contents exists in the cwd's repo.)

## What I'd do next

1. **Borrow exec-3's blast-radius map into exec-2's engine.** The map is the
   feature that makes this *land* with a human; exec-2 has the engine that
   should power it. That graft is the obvious strongest single artifact.
2. **Nail down the `classify_command` contract** (string vs token list) in the
   spec so the library API can't diverge — the one place the three builds
   actually disagreed.
3. **Ship it as a real PreToolUse hook** (currently documented, not built) and
   dogfood it against a live agent session for a week to tune the SAFE allow-set.
4. **Grade the EXTERNAL tier** (today a `POST /charges` and a `GET /search` both
   just "pause") — the next real increment of usefulness.
